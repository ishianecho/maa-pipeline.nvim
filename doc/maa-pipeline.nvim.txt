Neovim support for MaaFramework pipelines, reusing the parser and index from
Maa Support Extension <https://github.com/neko-para/maa-support-extension>


FEATURES                        *maa-pipeline.nvim-maa-pipeline.nvim-features*

- LSP features: completion, hover, navigation, references, diagnostics,
    Code Lens, code actions, inlay hints, document links, workspace symbols,
    and color support
- Filetype detection for Maa JSON/JSONC pipelines
- Run MaaFramework tasks directly from Neovim
- Runtime logs with native `ft=log` highlighting, source/kind highlights,
    Lua filtering, folding, and JSON or text export
- Screenshot cropping with ImageCropper

CONFIGURATION              *maa-pipeline.nvim-maa-pipeline.nvim-configuration*

The default configuration is:

>lua
    require("maa-pipeline.nvim").setup({
      stop_hotkey = nil, -- register a global stop hotkey; no hotkey when nil
      log = {
        key = {
          click = "<CR>", -- filter by token under cursor; false or "" disables it
          filter = "f", -- prompt for a Lua filter expression; false or "" disables it
          help = "g?", -- toggle the in-buffer help view; false or "" disables it
          reco = "d", -- open recognition detail; false or "" disables it
          close = "zc", -- close the fold under the cursor; false or "" disables it
          open = "zv", -- open the fold under the cursor; false or "" disables it
        },
        render = nil, -- custom render, see Going Further
      },
      trace = {
        key = {
          jump = "<CR>", -- jump to the node definition; false or "" disables it
          reco = "d", -- open recognition detail; false or "" disables it
          refresh = "r", -- refresh the snapshot; false or "" disables it
          close = "q", -- close the window; false or "" disables it
          help = "g?", -- toggle the in-buffer help view; false or "" disables it
        },
      },
    })
    
    vim.lsp.config("maa_pipeline", {
      cmd = nil, -- nil keeps the bundled Node.js command; set a list to use another command
      filetypes = { "json", "jsonc" }, -- native JSON filetypes; only pipeline files attach via root_dir gating
      root_markers = { "interface.json", "interface.jsonc", ".git" }, -- project root markers
      init_options = {
        mode = "auto", -- "auto": detect src/MaaCore; "maa": MAA syntax; "framework": MaaFramework syntax
        locale = "en", -- "en": English; "zh": Chinese diagnostics and hover text
        runtime = {
          data_dir = vim.fn.stdpath("data") .. "/maa-pipeline.nvim", -- MaaFramework downloads and logs
          version = "latest", -- "latest" resolves to the newest version; an exact semver pins it
          timeout = 60000, -- controller and Agent connection timeout in milliseconds; -1 disables it
          debug_mode = true, -- write MaaFramework debug logs
          save_draw = false, -- save annotated recognition drawings to `<data_dir>/logs/vision`
          save_on_error = true, -- save recognition data when a task fails
          reco_image_cache_limit = 64, -- number of recent recognitions whose drawings stay in memory for the detail view
          daemon = true, -- keep Maa agents alive between tasks
        },
      },
      capabilities = nil, -- nil uses Neovim defaults; provide extended client capabilities when needed
      on_attach = nil, -- called when the LSP attaches to a buffer
      handlers = {}, -- custom method handlers are merged with the bundled handlers
    })
    
    vim.lsp.enable("maa_pipeline") -- enable after applying overrides
<

On Windows, `maa-runtime` starts with administrator permissions because input
actions such as `Seize` require the same elevation as the target application,
while Neovim itself remains unelevated

ADVANCED                        *maa-pipeline.nvim-maa-pipeline.nvim-advanced*


LOG FILTER ~

The runtime log buffer is cleared automatically whenever a new task starts.
Press `f` in the runtime log buffer, type a Lua expression, leave it empty to
clear, press `g?` to toggle the in-buffer help view. Fields are available
directly without the `entry.` prefix:

>lua
    level == "error"
    level == "error" or level == "warn"
    family == "Reco"
    taskId == 3
    algorithm == "TemplateMatch"
    name and name:lower():find("startup", 1, true)
    raw and raw:find("recognition", 1, true)
<

Available fields: `level`, `source`, `family`, `phase`, `name`, `raw`, `kind`,
`ids`, `taskId`, `nodeId`, `recoId`, `actionId`, `wfId`, `reco`, `algorithm`,
`text`, `score`, `box`, `action`, `actionDetails`, `details`, `list`, `nested`,
`elapsed`, and the raw `entry`


NODE TRACE ~

`:MaaPipelineTrace` opens a dedicated tab: the node trace view on top and the
runtime log buffer in a bottom window. The tab also opens automatically
whenever a task starts. While a task runs, the view refreshes live from the
runtime notifications; press `r` to refresh manually.

Each executed node shows its status and metrics:

- `[hit ]` the node recognition succeeded (`runs`/`hit` counters and duration)
- `[miss]` the node was evaluated as a next-list candidate but never matched
- `[fail]` the node failed or was interrupted mid-run
- `[run ]` the node is currently executing

Child nodes reached through a parent’s `next` list are indented two spaces
per level, and `zc`/`zv` fold and unfold a node’s subtree (a node’s fold
starts at its own line, so `zc` on a parent hides its descendants). A node
referenced from several parents’ `next` lists gets one row per reference,
with runs, attempts, anchor, and duration counted separately for each. A
`[JumpBack]` tag after the status token marks a node entered through a
`[JumpBack]` link (execution returns to its parent when the subtree ends), and
`[Anchor:<alias>]` marks a node matched through an anchor alias. Metrics are
column-aligned under a header: action, executions, recognition attempts, and
the total duration.

Keymaps in the trace buffer (press `g?` in the buffer to toggle an in-buffer
help view listing the currently configured keys):

  Key    Description
  ------ ---------------------------------------------------------------
  <CR>   jump to the node definition in its pipeline JSON
  d      open the recognition detail for the node’s latest recognition
  r      refresh from the server
  q      close the window
  g?     toggle the help view

RECOGNITION DETAIL ~

Press `d` on a trace node or a log line with a recognition to open a new tab
with:

- the framework-annotated image of that recognition (ROI and result boxes, OCR
    results), served from the in-memory cache kept for the last
    `runtime.reco_image_cache_limit` recognitions and displayed through
    `vim.ui.img` (Kitty graphics protocol); the raw screenshot is shown when no
    annotated image was retained
- a text buffer with hit/miss, algorithm, box, best candidate (`score`, `text`,
    `count`, `label`), `all`/`filtered` counts, and nested recognitions

Without terminal image support only the text buffer opens. Details stay
available while the Maa instance lives: during a task, or after it when
`runtime.daemon = true`.

ARCHITECTURE                *maa-pipeline.nvim-maa-pipeline.nvim-architecture*

- Neovim runs the Lua client and starts the bundled Node.js LSP server
- The LSP server parses projects with `@nekosu/maa-pipeline-manager` and starts
    a separate `maa-runtime` process
- `maa-runtime` uses `@nekosu/maa-server` to create controller, resource, and
    task instances, then launches external agents declared in `interface.json`
